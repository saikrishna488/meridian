# Settings and notification integration changes

Storage replaces Device Manager in Settings navigation and launcher search. The
legacy `device-manager` preferences value remains accepted for bridge compatibility
and opens Storage. The unused Device Manager React page and tree styles are removed.
Backend inventory, driver and printer APIs remain for compatibility; opening Storage
never probes printers, PCI, USB topology, networking or kernel modules.
General retains existing system/processor/memory information. Wireless operations
remain on Wi-Fi and Bluetooth; individual BlueZ adapters now have their own switches
and a discovery adapter selector.

## Storage boundary

`protocol/src/lib.rs` owns StorageState/StorageVolume and capability types, with
ts-rs bindings generated by protocol tests. `shell/src/storage.rs` discovers block
topology with bounded `lsblk --json --bytes` and root usage with `df`. Root usage
includes the actual mounted filesystem (including overlay/network/Btrfs), rather
than summing partitions, bind mounts or subvolumes. Topology is flattened with
parent identifiers and deduplicated device paths. Read-only/removable flags,
filesystem types, loop/mapper/container types and mount points remain explicit.
Capacity discovery and block discovery can succeed independently. Bounded mountinfo
parsing adds mounted network/virtual filesystems without probing potentially stalled
remote filesystems; these entries offer Open only and label unknown capacity.

Mount/unmount/eject use the existing UDisks2 command client `udisksctl`, which owns
filesystem support and PolicyKit authorization. No shell interpolation, formatting,
partitioning, forced/lazy unmounting or encrypted-volume unlocking is implemented.
Each operation resolves a fresh inventory and checks its currently offered action.
System mount points, active swap and nested system partitions block unmount/eject.
USB disk ejection recursively unmounts children before requesting power-off. A busy
child aborts the operation. This can leave earlier children safely unmounted; refresh
before retrying. Mounted volumes open via GIO's default file manager. Unsupported
containers and loop devices expose information rather than pretend mount controls.
Optional UDisks unavailability disables mutation controls without hiding inventory.

## Capability reporting and failures

`settings.capability` is a Settings-scoped typed request accepting one feature.
`shell/src/capabilities.rs` probes NetworkManager device/radio state, BlueZ object
manager, compositor output-management, sysfs backlights or UDisks as needed.
It reports ready, disabled, hardware unavailable, service unavailable, unsupported,
permission denied or temporarily unavailable; it never branches on CPU architecture
or virtualization. Network connectivity is distinct from Wi-Fi availability and
means an active network connection, not a verified internet reachability test.
Wi-Fi saved profiles and nearby-network requests have separate error paths.
Bluetooth uses visible-page refresh at 15 seconds, backing off to 60 on failure,
with no silent failure swallowing. Explicit discovery remains bounded and opt-in.

Subprocess output is drained nonblockingly with bounded memory and deadlines;
inherited descendant pipes cannot keep reader threads stuck on join. Diagnostics
log only executable/status, never argument vectors, raw stderr or passwords.
The existing bridge ErrorBody/errorMessage contract remains the common error path.

## Displays and notifications

Every output-management registry/sync/configuration wait has a five-second deadline.
Configurations validate supported mode/refresh pairs, hot-plug topology, positions,
rotation, scale and at least one enabled output, both before test and before apply.
Failed apply attempts trigger best-effort restoration; accepted trials retain the
existing 15-second automatic rollback. GDK supplies read-only output information
when configuration is unavailable. Monitor geometry/hot-plug events invalidate the
open Displays page without continuous polling. Unsupported DDC/CI controls are
replaced with explanatory text. Primary display still selects Meridian's surfaces,
not a compositor-global primary-output policy.

Notifications uses a compact opaque black panel and shared hover/switch conventions,
with date/application grouping, expansion, actions, dismissal, empty/unavailable/error
states and keyboard focus handling. Opening the panel only reads its snapshot;
**Mark all read** explicitly clears unread state. DND persists through the existing
versioned preference file. The freedesktop D-Bus server and ownership behavior stay
intact. Expired entries remain history without active actions; default expiry is five
seconds, zero never expires. Replacements/dismissal/clear cancel obsolete timers so
live expiry sources stay bounded by retained entries. Pending guards prevent duplicate
UI action requests and the backend only invokes actions on active entries.

## Qualification and remaining work

Validation ran on Fedora 44 AArch64 with a headless labwc compositor. TypeScript,
production UI build and four UI test files passed. Rust tests passed 231 cases
with four intentionally ignored desktop-dependent cases. Focused native Settings
and Notifications checks passed at 100%, 125%, 150% and 200% scaling, including
Storage loading, unavailable system services, notification unread preservation,
action dismissal, opaque-black/no-blur styling and panel bounds. Run them with
`MERIDIAN_SETTINGS_ONLY=1 MERIDIAN_TEST_SCALE=2 bash tools/tests/wayland.sh`.
The standard scaler is wlr-randr; this environment lacked it, so scaling used a
temporary helper linked against Meridian's own display list/snapshot/apply API.

The follow-up review traced the intermittent 200% failure to transparent GTK
layer surfaces sometimes producing no initial render node. Without a first
Wayland buffer the compositor could not deliver output-enter, leaving the dock
and wallpaper invisible and unable to receive pointer events. The native host
now supplies a transparent one-pixel Cairo node for the first two frames, then
removes it. Native tests still check pointer pass-through and dock interaction;
they additionally check first-buffer delivery and exercise both outputs. The
integration fixture includes its own headless-only display scaler.

The generated bindings check compares two clean ts-rs exports with the working
tree, including missing and obsolete files, and therefore permits synchronized
uncommitted changes. Subprocess stdin writes are nonblocking and bounded;
storage operations are serialized, reject incomplete mount metadata, and check
kernel disk sequence identities when available. Display rollback failures retain
the trial for retry. Bluetooth refresh reports failures and backs off.

Required manual qualification: real NetworkManager/rfkill/password/PolicyKit flows;
multiple/USB-pass-through Bluetooth adapters, rejected pairing and battery support;
ext4/Btrfs/XFS/FAT/exFAT/NTFS removable volumes, busy files, mapper ancestry and
hot-unplug; physical DDC/CI monitors; VM resizing and physical output removal during
a trial; WebKitGTK/screen-reader focus and visual checks at 100/125/150/200%, reduced
motion and hover preferences. No physical-device or cross-distribution certification
is implied by mocked tests or the headless compositor suite.

Remaining technical debt: native NetworkManager/UDisks APIs could replace their
bounded CLI clients; Bluetooth signals could replace visibility-aware backoff;
network/virtual mount capacity and lifecycle need service-specific support;
encrypted unlocking is out of scope. Filesystem operation support remains owned by
UDisks, which can reject an offered action after permissions, hardware or mounts change.

## Changed-file map

- Frontend: Settings navigation/search in `settings.tsx`; new `storage.tsx`;
  wireless capability/adapter handling in `wireless.tsx`; output handling in
  `devices.tsx`; notification rendering and consolidated notification CSS.
- Shared UI: `appearance.ts`, `react.tsx`, `bridge.ts`, `tokens.css` and
  `floating-panels.css` integrate the persisted hover token and bounded popover
  lifecycle. Shared Glisse switches, Buttons, Dialog, Progress and AppIcon are reused.
- Backend: new `shell/src/storage.rs` and `capabilities.rs`; existing
  `settings_devices.rs`, `device_manager.rs`, `notifications.rs`, `desktop.rs`,
  `search.rs`, `shell.rs` and `shell/settings.rs` retain ownership of their domains.
  `services/src/displays.rs` implements bounded Wayland waits; `protocol/src/lib.rs`
  and generated bindings carry the new typed requests/states/events. Services adds
  the already-locked libc dependency for polling, with Cargo.lock updated accordingly.
- Tests/fixtures: UI surface/desktop feature tests, native `shell_tests.rs`,
  embedded Rust unit tests and the read-only preview bridge. `surface.rs` changes
  are rustfmt-only; `services/src/windows.rs` only adds the compatibility lint allowance.
- Removed: `ui/src/surfaces/settings/device-manager.tsx`, its obsolete tree styles,
  user-facing navigation/search entry and automatic notification read-on-open paths.
  Legacy bridge interfaces remain accepted; no backend hardware operations were deleted.

The follow-up validation and performance measurements are recorded in
[Settings review validation](SETTINGS-OVERHAUL-REVIEW.md). Generated bindings
remain uncommitted in the working tree as requested.
